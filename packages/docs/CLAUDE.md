# Radius Developer Documentation - Claude Code Guide

## Quick Start for Claude

This package is the source of https://docs.radiustech.xyz inside the `tools` monorepo. Run commands from `packages/docs`; build the SDK first (`pnpm --filter radius-sdk build`), because the docs import `radius-sdk` from the workspace.

**Writing rules:**

- Asset names: **RUSD** is the native fee asset; **SBC** is the payment asset in x402 flows; **USD** is a currency unit for prices, not a token
- Currency format: amount + asset, no $ symbol: `0.001 SBC`, `100 USDC`, `0.0001 USD`
- Sentence case headings: "Send a transaction" not "Send a Transaction"
- Active voice, present tense: "returns" not "will return"
- Our own examples use radius-sdk for x402, viem for other chain access, Foundry for contracts, and pnpm. The tooling page also documents Hardhat and ethers.js setup for readers who use them
- Max 3 callouts per page
- Document `radius-sdk` and `radius-cli` changes in the same pull request as the code; production docs deploy only after the packages are on npm (see Deployment)

**Essential commands:**

```bash
pnpm dev      # Development server at http://localhost:5173
pnpm build    # Production build to dist/public/ (static)
pnpm preview  # Preview production build
pnpm docs:markdown-audit  # Fail if an MDX component would leak into agent Markdown
pnpm docs:agent-check     # After build: fail on unparsed callouts or .md links with no file
```

## Critical Gotchas

These issues have caused problems before. Don't repeat them.

### Static hosting and Markdown twins

The site is served as static files by a Cloudflare Worker (Workers static assets), so `renderStrategy: 'full-static'` is required.

- Vocs writes Markdown twins to `dist/public/assets/md/<path>.md`; the pretty `/<path>.md` URLs only exist because `scripts/postbuild-static-markdown.ts` mirrors them after `vocs build`. Don't remove the `postbuild` script.
- Vocs leaves page links in twins extensionless (its server serves Markdown at the page URL to agents). The postbuild script rewrites them to `/<path>.md` so agents stay on Markdown.
- ` ```json ` blocks must parse (`pnpm docs:validate` checks). Mark partial or annotated JSON as ` ```jsonc `.
- Callout titles must use `:::note[Title]`. `:::note Title` is not parsed: it renders as literal text in HTML and as `\:::note` in twins.
- Server-only Vocs features (MCP server, AI search, feedback, `/api/og`) do not work on static hosts.
- **Build output directory is `dist/public`**; `assets.directory` in `wrangler.jsonc` points the Worker at it.

### Waku is pinned exactly

`waku` is pinned to `1.0.0-rc.1` in `package.json`. Vocs 2.10.0 declares `waku >=1.0.0-rc.1`, but `1.0.0-rc.2` fails `vocs build` (`Rolldown failed to resolve import "virtual:vite-rsc-waku/html-transform"`). Earlier waku prereleases broke Vocs only at runtime (pages hydrated to a blank screen), so after bumping either package, check a built page in a browser, not just the build. Bump the pin only together with a Vocs release that supports it.

### Config functions are serialized

Vocs 2 serializes `head`, `ogImageUrl`, and other config functions with `Function.prototype.toString()` and re-creates them in the page bundle.

- They must not reference module-scope variables or helpers. `head` in `vocs.config.ts` is built with `new Function` so precomputed data travels with it.
- Vocs renders `<Head>` twice per page (root without frontmatter, layout with it); emit per-page tags only when `context.frontmatter` exists.

### Custom MDX components need `toMarkdown`

Vocs generates agent Markdown from the MDX AST, not from React.

- A component used as a standalone `<Foo />` (no props, no children) must expose `Foo.toMarkdown()` returning mdast nodes (see `docs/components/FeatureCards.tsx`). Keep card/list content in a data module so HTML and Markdown share one source.
- Components with props (`<TransactionCost field="…" />`), plain HTML JSX, `{CONSTANT}` expressions, callouts, and `# Title [Subtitle]` are handled by `docs/remark-llm-output.ts`.
- `pnpm docs:markdown-audit` (run in CI) fails when a component is left unrendered.

### Page actions and Ask AI

- "View as Markdown" and "Copy for LLM" below every page title come from `docs/components/PageActions.tsx`, inserted by `docs/rehype-page-actions.ts` (`markdown.rehypePlugins`). Vocs 2 has no slot below the title. Do not add it to pages by hand. Rehype plugins run only for HTML, so agent Markdown is unaffected.
- Vocs's floating "Ask AI" bar (it covers content) and its "Copy page for AI" button (a duplicate of PageActions) are hidden in `_root.css`.

### Logo Configuration

```typescript
// CORRECT - logos render
logoUrl: { light: '/logo-light.svg', dark: '/logo-dark.svg' }

// WRONG - silently ignored, no logos
logo: { light: '/logo-light.svg', dark: '/logo-dark.svg' }
```

### basePath for sub-path previews

Production is served at the domain root. To serve a build under a sub-path, set `VOCS_BASE_PATH` (for example `/docs`) when building; `vocs.config.ts` passes it to Vocs as `basePath`.

### Vocs Subtitle Pattern

Use bracket syntax to avoid unwanted H2 borders:

```mdx
# Page Title [Subtitle text here]

## First Section
```

This keeps subtitle inside `<header>`, preventing double borders.

## Deployment

The site is the `radius-docs` Cloudflare Worker (`wrangler.jsonc`). Workers static assets serve `dist/public`, including `public/_redirects` and `public/_headers` (which marks every `workers.dev` host, previews included, `noindex`); `worker/index.ts` runs only for the paths in `assets.run_worker_first`. Under `/api/try/*` it is the backend of the interactive "Try Radius" components (`docs/components/try/`, used on `/try`), a testnet faucet proxy (the faucet API sends no CORS headers) and priced testnet routes built with `radius-sdk/hono`. Payments go to `TRY_PAY_TO` in `wrangler.jsonc`. For the agent-facing files (`*.md`, `llms.txt`, `llms-full.txt`, `robots.txt`, sitemaps) it serves the static asset unchanged and records each request twice, because Cloudflare Web Analytics only counts browsers that run its script: an `agent file` line in Workers Logs (kept 3 to 7 days, for debugging) and a data point in the `docs_agent_fetches` Analytics Engine dataset (for weekly KPIs; `worker/index.ts` documents its columns, which are append-only). Neither records an IP address, query string or body. Keep HTML pages asset-first: browsers are already counted, and every Worker invocation is billed. Run it locally with `pnpm build && pnpm wrangler dev`; `vocs dev` serves the pages only, so the components' API calls fail there.

The `docs.radiustech.xyz` custom domain is managed in the Cloudflare dashboard, not in `wrangler.jsonc`: listing it there makes `wrangler deploy` call the custom-domains API, which needs zone and DNS permissions the CI token deliberately lacks.

- `.github/workflows/docs.yml`: format, lint, typecheck, validators, build, `docs:agent-check` and `docs:sitemap-check` on pull requests; same-repo pull requests get a preview Worker version (`pr-<number>` alias, URL commented on the PR).
- `.github/workflows/docs-deploy.yml`: production. Called by `release.yml` after every npm publish, or run by hand for a docs-only release (refused while `radius-sdk`/`radius-cli` changesets are pending). Moves the `docs-live` tag to the deployed commit; it refuses to deploy a ref that does not contain `docs-live`'s commits. Live fee constants are fetched (`pnpm fetch-cost`) only there.

## Content Pages

Three areas, each with its own sidebar in `vocs.config.ts`; the area list is in `docs/areas.ts`. The top nav and a Discover / Build / Reference switcher at the top of the desktop sidebar (`SidebarHeader` slot, `docs/components/AreaSwitcher.tsx`) link them; on mobile, Vocs shows the areas as a menu drop-down.
